Hi Seyong,

I had a look at the full job log. It is not an output size issue, and the upload step is not involved: the job fails before it.

Root cause
The log says: "Serialized task 13:0 was 182,966,612 bytes, which exceeds max allowed: spark.rpc.message.maxSize (134,217,728 bytes)".
It is triggered by the .head(1) in first_matching_key (data_agg_aux_funcs.py, line 37), called from build_join(dfs["T20"], dfs["T01"], "LGD").

The input files are read with pandas on the driver and converted with createDataFrame(pd_df). A Spark DataFrame created from pandas has no file source the executors can read: its data is embedded inside the tasks themselves. T20 (df_t20_x200.csv) is large enough that a single task exceeds the 128 MB RPC limit. The head(1) only returns one row, but it still has to ship that whole partition. The broadcast of the key subset of T01 is not the problem.

Quick fix (no code change)
Add spark.rpc.message.maxSize = 512 in the recipe's Spark configuration (Advanced tab). This should unblock the run, but it will fail again if the input grows.

Recommended fix
1. Read the large CSV files with Spark instead of pandas, so the executors read them directly. If the input managed folder is on HDFS:

    def download_tab(input_folder, dataset_name, spark):
        extension = dataset_name.split('.')[-1]
        if extension == 'csv':
            root = input_folder.get_info()['accessInfo']['root']
            return spark.read.csv(root.rstrip('/') + '/' + dataset_name, header=True, inferSchema=False)
        elif extension == 'xlsx':
            with input_folder.get_download_stream(dataset_name) as stream:
                pd_df = pd.read_excel(io.BytesIO(stream.read()))
            return spark.createDataFrame(pd_df)

   With inferSchema=False, all columns are read as strings, so numeric columns need an explicit cast (pandas used to infer the types). If the folder is not on HDFS, create a "Files in folder" dataset on the CSV files and read it with dkuspark.get_dataframe.

2. Cache df_gran once it is created. first_matching_key runs one Spark job per candidate key set, and build_join joins again afterwards, so without a cache the data is recomputed each time.

3. For the output, the standard approach in DSS is to write to a DSS dataset with dkuspark.write_with_schema(dataiku.Dataset("..."), spark_df), and add an Export recipe if a CSV file is needed. toPandas() + upload_data loads everything on the driver, and spark_df.write.csv to the folder root only works for HDFS folders and produces a directory of part files.
